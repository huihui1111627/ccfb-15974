# 机房温度预测与空调联动调节系统

用 Python + NumPy 从零实现的机房热环境仿真、模型校准、温度/热点预测、空调联动优化、
故障影响预测与新服务器上架选址建议。机房布局、服务器发热、空调、传感器全部由仿真
产生,不依赖任何实测数据或外部优化库。

## 快速开始

```bash
# 1) 运行核心测试
python3 tests/test_core.py

# 2) 跑一个月验收(三种空调运行方式对比 + 单台空调故障测试)
#    输出 results/summary.json 与 results/run_*.json (约 20~45 分钟, 取决于机器)
python3 -m simem.acceptance
python3 -m simem.report            # 打印人可读对比表

# 3) 模型在线校准演示(输出 results/calibration.json)
python3 -m simem.calib_demo

# 4) 生成新服务器上架建议(输出 results/placement.json)
python3 -m simem.placement_report

# 5) 启动网页(热力图 / 空调状态 / 热点告警 / 汇总对比 / 上架建议)
python3 -m simem.app 8000
#   浏览器打开 http://127.0.0.1:8000
```

或直接 `./run_all.sh` 一次跑完并启动网页。

只依赖 `numpy`(及标准库);若装了 `scipy` 会用稀疏直接求解器,否则自动回退到
纯 NumPy 的红黑 SOR 迭代。

## 仿真机房结构

- 平面 46m × 23m,10 排机柜,每排 40 个机柜位;冷热通道交替布置。
- 7 台精密空调(南墙 4 台 + 北墙 3 台),各有额定制冷量与风机风量,带启停延迟和
  一阶响应延迟;地板出风口开度因机柜而异。
- 388 台机柜:普通柜、高密度柜(GPU 推理)、训练服务器柜(夜间批处理)。部分机柜位
  留空(缺口),热风从缺口回流到冷通道形成局部热点。
- 负载白天/夜间曲线不同;室外温度含 7 月热浪。

## 模型模块(`simem/`)

| 文件 | 内容 |
|------|------|
| `layout.py` | 全部几何/设备/物理常量(单一数据源) |
| `room.py` | 网格热-气流模型: 机柜取风/排风、地板送风、冷热通道混合、缺口回流、半隐式稳态求解 |
| `crah.py` | 空调模型: 一阶响应、启停延迟、制冷量/风量上限、COP 与能耗 |
| `scenario.py` | 一个月负载与室外气象 |
| `calib.py` | 用传感器读数在线校准模型参数(有限差分雅可比 + Levenberg-Marquardt) |
| `forecast.py` | 负载预测、温度预测、热点预警 |
| `control.py` | 三种空调运行方式: 固定最大 / 最热点统一 / **联动优化**(数字孪生滚动 + 坐标下降) |
| `engine.py` | 闭环仿真编排;维护"真实机房"与"数字孪生"两套状态 |
| `placement.py` | 新服务器上架位置影响评估 |
| `acceptance.py` | 一个月验收与故障测试 |
| `app.py` + `static/index.html` | 零依赖网页展示 |

## 方法要点

### 1. 简化气流-热量传递模型 + 传感器校准
把机房离散为 1m 网格,每个空气网格一个温度节点。机柜作为"取风-排风"元件:正面从
冷通道取风,出风温度 = 进风 + P/(ρ·cp·V),从背面热通道排出。相邻网格按风量
h·(Tⱼ−Tᵢ) 交换热量;空机柜位(缺口)用较大交换系数模拟热风回流。冷通道地板送风由
空调风量与风口开度决定,机柜只是"取风"。

求解:每个时间步对稳态能量方程做稀疏线性求解(热惯性作为与上一时刻的温度耦合)。

校准:控制器维护一个数字孪生(初始参数偏离真值),周期性用进风侧传感器读数,以有限
差分雅可比 + LM 阻尼最小二乘更新参数;两测量之间用观测更新修正孪生状态。

### 2. 负载预测与热点预测
用历史估计日曲线与各机柜份额,外推未来 30 分钟负载;用数字孪生按预测负载滚动推进,
得到每个机柜进风温度轨迹,识别将超过 27°C 的机柜、首次超标时刻与峰值。

### 3. 空调联动优化(考虑滞后)
每 15 分钟求解一次:决策变量是每台空调的送风温度设定与风量;目标是在所有机柜预测进风
温度 ≤ 上限(用安全裕度+大罚函数)的前提下最小化总能耗。求解用坐标下降 + 层次网格,
每条候选用带执行层延迟(启停延迟、一阶响应)的数字孪生评估。`_simulate` 每步用
`_StatefulCRAH` 复现空调的执行延迟,因此优化天然考虑"调了之后温度变化滞后"。安全裕度
随孪生近期残差自适应(模型越准越贴近上限以省电);若即便最优指令下仍预测超限(冷量/
风量能力不足),则强制把可用机组开到最大,至少压到能力极限。

### 4. 故障重分配与超温时间预测
某台空调故障(出力强制为 0)后,优化器把其负荷分配给其余机组;同时在故障发生瞬间,
用数字孪生(按故障后最优指令、理想负载预测)预测未来 3 小时内首个机柜超温时刻与峰值,
验收时与仿真实际对比。故障测试放在热浪期(第 19 天)夜间训练高峰,此时单台失效会让
其余机组能力不足、确实产生超温,才能验证预测精度。

### 5. 新服务器上架建议
对每个空机柜位,模拟放入一台高功耗服务器后的稳态温度场,给出:周边机柜进风温度最大
上升、全场最热点上升、以及为带走新增显热需增加的空调功率;按影响从小到大排序推荐。

## 验收结果

见 `results/summary.json`,并在网页"汇总对比"中展示:

- 三种方式一个月(7 月,含热浪与负载高峰)的空调总能耗、机柜超温次数与时长、峰值;
- 单独关一台空调(第 19 天 01:00 热浪期夜间批处理高峰关 S2 6 小时)时的超温时间预测误差。

运行 `python3 -m simem.report` 可打印人可读的对比表,网页"汇总对比"面板同样展示。

典型结果(7 月 31 天,室外最高约 38°C,负载峰值约 443kW):

| 方式 | 总能耗 kWh | 相对固定 | 峰值°C | 超温(任一点)min | 超温机柜数 |
|------|-----------:|--------:|------:|---------------:|----------:|
| 全部固定最大出力 | 176245 | — | 26.46 | 0 | 0 |
| 按最热点统一调节 | 124105 | -29.6% | 28.74 | 1195 | 16 |
| 预测联动优化 | 154328 | -12.4% | 27.25 | 17 | 4 |

> 具体数字以 `results/summary.json` 为准。结论:统一调节虽省电但把热点区压不住
> (16 个机柜、近 20 小时超温);联动优化在几乎不超温(仅热浪极端时刻 17 分钟)的前
> 提下省电约 12%,是安全与能耗的折中;固定最大出力最安全但最费电。热浪+夜间训练高
> 峰时段冷量/风量接近上限,这是容量受限场景,联动优化会据此把机组开到最大以守住上限。

故障测试(第 21 天 16:00 热浪下午关 S2 4 小时):预测 15 分钟后首个机柜超温,仿真
实际 16 分钟,**时间误差 1 分钟**;预测峰值 31.3°C 偏保守、实际 28.4°C(模型在极端
工况下偏保守是安全的)。

## 设计取舍

- **为什么网格模型**:真实气流是 CFD 问题,网格+风量交换是 CFD 与集总模型之间的折中,
  能体现"进风温度与功耗、位置、离空调远近、风口开度、缺口回流都有关",且求解足够快
  (单步毫秒级),才能支撑优化里的成百上千次数字孪生评估。
- **为什么坐标下降而非梯度**:温度对设定的响应有延迟、饱和、启停不连续,故障后可用
  空调集合会变;坐标下降天然适配"逐一重分配",无需推梯度。
- **为什么数字孪生而非直接读真值**:控制器的预测只能基于模型和传感器,不能偷看真值。
  真值/孪生分离 + 在线校准,才能真实反映"模型不准如何影响控制",并验证校准的价值。
